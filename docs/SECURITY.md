# 信息与权限边界

## 三种边界分别保护什么

| 边界 | 保护对象 | 由谁执行 |
| --- | --- | --- |
| 网页认证 | 谁能打开工作台、发送指令 | 访问码、来源校验、CSRF；公网入口另加身份与 TLS |
| 设备连接 | A 可以对 B 调用什么 | 专用 SSH 公钥、固定 RPC 命令、主机指纹 |
| 任务与网络隔离 | 工作负载能读什么、从哪里联网 | 远端执行器、只读挂载、网关与独立守卫 |

安装网页控制台只建立第一层及客户端连接能力，不会自动建立完整的第三层。

## 信息放在哪里

| A 保存 | B 保存 | 不自动跨设备传递 |
| --- | --- | --- |
| 管理配置、订阅、专用私钥、访问码 | Claude 登录、项目、会话、附件 | 主机环境变量、SSH agent、浏览器配置、云凭据 |

Starship 在 B 上运行，可以使用 B 自己的项目与账号。它不是给 B 再创建一层虚拟机。
用户主动发送的文件和消息仍可能包含个人信息；网络隔离不等于内容匿名。

## 已有保护

- 网页只监听指定回环／私有接口，检查 Host、Origin、允许子网和 CSRF。
- 浏览器不能将任意 shell 命令、本机路径或 SSH 目标交给管理接口执行。
- 配对工具只增加固定命令规则，不开放通用 shell，不关闭主机密钥校验。
- 订阅只导入支持的节点字段；不会套用其脚本、规则、DNS 或 DIRECT 回退。
- 附件按路径、类型、大小和完整性处理；消息只做简繁转换，不加入语义敏感词拦截。
- 公网使用 Access + Tunnel 等受保护 HTTPS 入口；不要直接映射 HTTP 端口。

网络与计算隔离仍需在实际设备上验收，见[网络检查表](NETWORK.md)与[算力接入](SERVICES.md)。
